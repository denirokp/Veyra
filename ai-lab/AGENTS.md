# AGENTS.md — AI Lab (корпоративная память Avito) для Codex

Инструкции для агента (Codex и совместимых) при работе с MCP-сервером
`ai-lab`. Это адаптация навыка `skills/SKILL.md` под окружение без механизма
«skills» — здесь всё в одном файле, без подгружаемых `references/`.

## Подключение сервера

```toml
# ~/.codex/config.toml  (или проектный .codex/config.toml)
[mcp_servers.ai-lab]
url = "https://veyra.fly.dev/mcp"
```

Сервер открытый — токен не нужен. Если включат `MCP_AUTH_TOKEN`, добавь
`bearer_token_env_var = "AILAB_TOKEN"` и положи токен в переменную окружения.

## Когда применять

Когда пользователь просит: «проверь инициативу», «нет ли противоречий с
прошлыми решениями», «что обещали и не сделали», «где серые зоны / пробелы»,
«что мы знаем про X», «помоги написать / отревьюить документ по теме». Тогда
бери данные из инструментов `ai-lab` и рассуждай по правилам ниже.

## Принцип

`ai-lab` — **слой данных**: фрагменты документов, полные тексты,
предвычисленные расхождения и обещания. LLM на его стороне нет.
**Рассуждение — твоя работа.** Инструменты приносят сырьё, анализ пишешь ты.
Инструменты недоступны → скажи подключить сервер, находки не выдумывай.

## Корпус — два пласта

- **Стратегия** — что решили (Strategy/Action Plans, Deep Dives, OKR).
- **Регламенты** — как делаем (лиды, CRM, онбординг, T&S, методологии).

Смотри в **оба** пласта: обещание в стратегии проверяется наличием процесса
в регламенте; метрика в стратегии — определением KPI в регламенте. Не
отсекай половину корпуса по жанру — пересечения и есть ценные находки.

## Инструменты

| Инструмент | Что отдаёт |
|---|---|
| `search_corpus(query, top_k)` | релевантные фрагменты по теме |
| `get_document(doc_id)` | полный текст документа |
| `list_documents()` | список (id, название, статус, тип, `is_anchor`) |
| `find_numeric_contradictions(query?, status?)` | числовые расхождения; строки несут `status`, `created_at` |
| `find_logic_contradictions(query?, status?)` | логические расхождения |
| `find_open_promises(query?, status?)` | обещания |
| `mark_finding(kind, finding_id, status, note?)` | пометить находку (переживает сессии) |
| `corpus_stats()` | сводка + `last_indexed_at` (свежесть) |
| `health()` | доступность движка |

На тематическом вопросе передавай `query` в `find_*` — сервер вернёт только
релевантные строки (ловит и синонимы), не тяни всю таблицу. `status`
сужает по состоянию. Предвычисленные таблицы могут быть пусты (бульон не
сварен) — тогда ищи расхождения сам через `search_corpus` + `get_document`.

## Жёсткие правила вывода

1. **Язык** — русский; англ-термины из документов (GMV, churn, TRI*M) как есть.
2. **Каждый факт — со ссылкой на документ-источник.** Не выдумывай источник.
3. **Разделяй ФАКТ и ГИПОТЕЗУ.** Гипотезу помечай явно.
4. **archived / draft** — только как контекст, с пометкой ⚠️.
5. **Данных мало — скажи прямо.** Не достраивай догадками.
6. **Контракт охвата.** «Расхождений / пробелов нет» — только с тремя
   вещами (через `corpus_stats`): **(а)** сколько — «N из M по теме»;
   **(б)** что — попал ли ключевой (`is_anchor`) документ по теме в выборку;
   **(в)** на когда — таблицы `find_*` отражают корпус на `last_indexed_at`,
   а не «сейчас». «Чисто» без этих трёх — запрещено.
7. **Не сдавайся с первого поиска.** <3 фрагментов → переформулируй
   (RU↔EN, сокращение↔полная форма, синонимы), 2–3 попытки.
8. **Под каждой находкой — бизнес-смысл одной строкой** (не «5,54% vs 7%», а
   что это значит и что сделать).
9. **Внешние (рыночные) утверждения — с рабочей ссылкой.** Корпус и внешку
   визуально разделяй.
10. **Документ за пользователя целиком не пишешь** — grounded-черновик с
    цитатами и [TODO], финал за человеком.

## Что НЕ расхождение

Расхождение — только если совпали **имя метрики, период и единица**, а
значения разные. Разные метрики с похожим словом, разные периоды
(динамика), разные единицы — **не** расхождение. Одинаковое значение из
двух версий одного документа (`(1)`/`(2)`, черновик рядом с `actual`) —
**дубль, а не расхождение**: не показывай дважды, опирайся на свежую/actual.

## Плейбуки (кратко)

- **Числовые расхождения:** `find_numeric_contradictions(query=тема)` →
  `search_corpus`/`get_document` для проверки → таблица со светофором + охват.
- **Логические:** `find_logic_contradictions(query=тема)` → противоположные
  тезисы по одной теме с цитатами из обоих документов.
- **Обещания:** `find_open_promises(query=тема)` → цитата, документ, срок,
  владелец; отметь просроченные/без дедлайна/без владельца.
- **Пробелы (что забыли):** `search_corpus` → темы/риски, упомянутые, но не
  закрытые планом/ресурсом/владельцем/метрикой; каждый с цитатой.
- **Неувиденное (чего не видим):** в корпусе этого нет — нужен веб-поиск;
  подавай как гипотезы с рыночной ссылкой, не как факт корпуса.
- **Проверить инициативу:** `search_corpus` + `find_*` + `find_open_promises`
  → что подтверждается / противоречит / чего не хватает, с цитатами. Вердикт
  approve/reject НЕ выдавай — аргументированная рекомендация, решение за
  человеком.
- **Что знаем про X / онбординг:** `search_corpus` + `list_documents` +
  `get_document` → синтез с цитатами и охватом.
- **Ревью/со-написание:** изучи эталон жанра (`get_document` по 2–3 докам
  того же типа) → разбор по осям текст/корпус/нарратив → допиши в стиле
  корпуса, числа не выдумывай ([TODO]), спорное выноси вопросом.

## Память находок между сессиями

Строки `find_*` несут `status` (open/resolved/dismissed/reviewed/fulfilled)
и `created_at`. Показывай `open` отдельно от уже закрытого (не подавай
resolved как новое); на «что нового» сравни `created_at` с названной датой;
разобрали — предложи `mark_finding(...)`, но помечай **только по явному
согласию** пользователя.

## Формат и тон

- Ответ на первой строке; сначала вывод, потом доказательство.
- Числовые находки — таблицей со светофором 🔴critical 🟡medium 🟢low
  ⬜unknown (`severity` из `find_*`; сам оценивай тем же строгим правилом).
- Цифры точно как в документе, не округляй. Тех-жаргон (chunk, embedding,
  RAG, MCP, retrieval) в ответ не тащи. Мусорные данные — «содержательная
  часть не извлекается, смотри оригинал», без жаргона.
- В конце — 2–3 конкретных follow-up вопроса по теме.

## Самопроверка перед ответом

Каждый факт со ссылкой? Числа точно как в источнике? Под находкой —
бизнес-смысл? Охват числами + ключевой документ + дата свежести? Смотрел оба
пласта? На «ничего не нашёл» — переформулировал ≥2 раза? Тех-жаргона нет?
