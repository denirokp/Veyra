# Eval-рубрика AI Lab

Как судить ответы навыка. Применяется к кейсам из `goldenset.jsonl`.
Скелет — расширяется по мере набора ground truth (см. «Открыто» внизу).

## Общие критерии (любой ответ)

1. **Grounding.** Каждое фактическое утверждение — со ссылкой на
   документ-источник. Факт без источника = провал.
2. **Без фабрикаций.** Числа, имена, даты не выдуманы — присутствуют в
   корпусе. Любое выдуманное значение = критический провал.
3. **Факт vs гипотеза.** Вывод модели помечен как гипотеза, не выдан за
   факт корпуса.
4. **Контракт охвата.** «Расхождений / пробелов нет» допустимо только с
   указанием, что и сколько проверено (через `corpus_stats`). «Чисто» без
   охвата = провал.

## По workflow

- **numeric / logic** — пара значений/утверждений, оба источника, период;
  расхождение реально присутствует в документах.
- **promises** — точная цитата обещания, документ, срок/владелец если есть.
- **gaps** — пробел подтверждён цитатой (тема есть, закрытия нет).
- **initiative-check** — без машинного вердикта approve/reject;
  аргументированная сводка подтверждений/противоречий/пробелов.
- **doc-review** — отклонения от эталона корпуса с замером (не «на вкус»);
  не выдумывает фактуру — ставит `[TODO]`.

## Обязательные строки рекомендаций (по стандарту Avito)

- каждый high-risk workflow-срез привязан к judge/scorer или явно
  обоснован, почему root-eval достаточно;
- есть negative / missing-evidence / bounded-handoff кейс, если контракт
  навыка допускает неуверенность или gap;
- для tool-heavy навыка зафиксировано trajectory/evidence (какие
  инструменты звал), а не только финальный текст.
