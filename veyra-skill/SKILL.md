# Veyra — сверка инициатив со стратегическим корпусом

> **Статус: ЧЕРНОВИК (Фаза 1, Трек F).** Скрипты вызывают `veyra-mcp`,
> который сейчас возвращает заглушки. Содержательные ответы появятся
> после Фазы 2 (Трек E) — заливки реальной логики детекторов в MCP-сервер
> по прохождении гейта. Образец упаковки — скилл `quality-metrics`
> (`stash.msk.avito.ru/agent/qa-skills`).

## Когда вызывать

- «Проверь инициативу X на согласованность с корпусом»
- «Нет ли противоречий с прошлыми стратегическими решениями?»
- «Что мы обещали и не сделали?»
- «Где у нас серые зоны / что упустили?»

Не вызывать для простого поиска по Confluence — у Veyra своя ниша
(логика противоречий), это не замена поиску релевантности.

## Режим 1 — Диалог

Пользователь задаёт вопрос → скилл вызывает `veyra-mcp.check_initiative`
(или `find_contradictions`) → возвращает структурированный ответ:
каждое расхождение сопровождается точной цитатой и ссылкой на документ-
источник. Без цитаты находка не показывается.

## Режим 2 — Отчёт в Confluence

Скилл строит страницу в Confluence в формате 3-колоночной таблицы
(как у `quality-metrics`):

| Расхождение | Источник | Рекомендация |
|---|---|---|
| … | документ + раздел | … |

## Как устроено

```
veyra-skill/
├── SKILL.md              # этот файл
├── scripts/
│   ├── check_init.py     # вызов veyra-mcp.check_initiative
│   └── report.py         # сборка Confluence-отчёта по результату
└── references/
    └── README.md         # инструкция для пользователя
```

Конфигурация — через переменные окружения:
- `VEYRA_MCP_URL` — адрес MCP-сервера (по умолчанию `http://localhost:8000`)
- `VEYRA_MCP_DEV_TOKEN` — токен dev-режима (опционально)

## Чего скилл НЕ делает

- Не пишет документы за пользователя — финальный текст пишет человек.
- Не выдаёт находку без цитаты из источника.
- Не отправляет конфиденциальный текст во внешний веб-поиск.
