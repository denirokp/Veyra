# Veyra — плейбук работы с корпоративной памятью

## Принцип

MCP-сервер `veyra` — это **слой данных**. Он только подтягивает
материал из корпоративной памяти: фрагменты документов,
предвычисленные расхождения и обещания. **Рассуждение — твоя работа.**
Veyra приносит книги, аналитику пишешь ты.

Если инструменты `veyra` недоступны — скажи пользователю подключить
MCP-сервер. Не выдумывай находки.

## Инструменты veyra (только данные, без LLM на их стороне)

| Инструмент | Что отдаёт |
|---|---|
| `search_corpus(query)` | релевантные фрагменты документов по теме |
| `find_numeric_contradictions()` | готовая таблица числовых расхождений |
| `find_logic_contradictions()` | готовая таблица логических расхождений |
| `find_open_promises()` | готовая таблица незакрытых обещаний |
| `list_documents()` | список документов корпуса |
| `get_document(id)` | полный текст документа по id |
| `corpus_stats()` | сводка по корпусу |

## Плейбуки — как из этих данных решать задачи

**Проверить инициативу.**
1. `search_corpus` по ключевым темам инициативы — собери релевантные фрагменты.
2. `find_numeric_contradictions` + `find_logic_contradictions` — есть ли уже зафиксированные расхождения по теме.
3. `find_open_promises` — что по теме уже обещали.
4. Сам сопоставь инициативу с собранным: что подтверждается, что противоречит, чего не хватает. Итог формулируй с цитатами из фрагментов. Формальный вердикт approve/reject как «машинный» не выдавай — он гало́генен и не прошёл отдельный гейт (ТЗ §13.6); давай аргументированную рекомендацию, решение — за человеком.
5. По запросу — рыночный контекст: как похожее делают снаружи (свой веб-поиск, каждое внешнее утверждение со ссылкой на источник).

«Серые зоны» — это **две разные задачи**, не путай их.

**Найти пробелы — что забыли (4a).** Смотрит в корпус.
1. `search_corpus` по теме (или `list_documents` для обзора).
2. Сам проанализируй: какие темы упомянуты в документах, но без ресурсов / владельца / метрик / плана — «провалили между стульев». Каждый пробел — с цитатой, на чём основан вывод, и с охватом проверки.

**Найти неувиденное — чего мы не видим (4b).** В корпус смотреть бесполезно — того, что упустили, в документах нет. Нужна внешняя рамка:
1. `search_corpus` — что по теме уже есть внутри (чтобы понять, что у нас закрыто).
2. Свой веб-поиск — практики, идеи, подходы на рынке.
3. Сопоставь: какие идеи/направления есть снаружи, но не у нас. Каждую гипотезу подавай с пометкой, на чём основана (рыночный источник со ссылкой). Это не «факт корпуса», а гипотеза для обсуждения.
   _(Когда подключены дашборды — добавляется вторая рамка: какие метрики стоит смотреть, но не смотрим. Пока — Фаза 2.)_

**Помочь написать документ.**
1. `search_corpus` по теме — собери grounded-факты и формулировки команды.
2. Сам напиши черновик, опираясь ТОЛЬКО на найденные факты. Где факта в корпусе нет — помечай как предположение. Финальный текст — за человеком.

## Режим отчёта в Confluence

Собранный тобой результат разбора (ответ, факты с источниками,
расхождения, охват проверки) передай в `scripts/report.py` как JSON
через stdin — скрипт форматирует его в Confluence-разметку. `report.py`
не вызывает `veyra` и не рассуждает: он только форматирует то, что ты
уже собрал.

## Правила

- Каждое расхождение — с точной цитатой и документом-источником.
- «Расхождений нет» — только с указанием охвата проверки.
- Не выдумывай находки, которых нет в данных veyra.
- Документ за пользователя не пишешь целиком — даёшь grounded-черновик.
