# Документация Veyra — индекс

Набор документов проекта Veyra (внутренний кодовик — «Хроника»).
Каждый документ самодостаточен; этот файл — карта набора и порядок чтения.

## Документы

| Документ | Назначение | Кому читать |
|---|---|---|
| [`SYSTEM.md`](SYSTEM.md) | Полное описание системы с нуля: бизнес-проблема, что делает, архитектура, структура кода, слабые места, глоссарий. | Новичку — первым. |
| [`ARCHITECTURE.md`](ARCHITECTURE.md) | Глубже про слои, модель данных, потоки, масштаб, безопасность. Источник правды по архитектуре. | Тем, кто разрабатывает или интегрирует. |
| [`TZ-Veyra.md`](TZ-Veyra.md) | Техническое задание (актуальная версия — v1.4). Возможности, фазы, гейт, принципы, открытые вопросы. Источник правды по требованиям. | Перед планированием работ. |
| [`SCALE-PLAN.md`](SCALE-PLAN.md) | План загрузки корпуса 100→300 документов: пошагово, чем мерить, риски. | Перед индексацией корпуса. |
| [`CASES-PLAN.md`](CASES-PLAN.md) | План вывода всех бизнес-кейсов на целевой путь (Claude через veyra-mcp): этапы, матрица готовности, что строить. | Для планирования разработки. |
| [`gate_report.md`](gate_report.md) | Результаты гейта детекторов Фазы 1: что проверено, метрики, границы достоверности. | Чтобы понять, что доказано, а что нет. |
| [`STATUS.md`](STATUS.md) | Снимок статуса сессии на дату. Устаревает — сверяйте дату. | Для быстрого «где мы сейчас». |

## Порядок чтения

1. **`SYSTEM.md`** — понять систему целиком.
2. **`ARCHITECTURE.md`** — устройство слоёв и данных.
3. **`TZ-Veyra.md`** — требования, фазы, принципы.
4. **`SCALE-PLAN.md`** — как растить корпус.
5. **`gate_report.md`** + **`STATUS.md`** — что доказано и где проект сейчас.

## Приоритет при расхождениях

- По **требованиям** — `TZ-Veyra.md` (в нём раздел 13 перекрывает разделы 1–12).
- По **архитектуре** — `ARCHITECTURE.md`.
- По **текущему состоянию** — свежий PR / git-лог; `STATUS.md` — снимок, может устареть.
