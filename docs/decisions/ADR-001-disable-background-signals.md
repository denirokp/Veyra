# ADR-001: Отключить background signals по умолчанию

**Дата:** 2026-05-12  
**Статус:** Принято

## Контекст

При индексировании документа запускается «pipeline skills»:
1. `extract_entities` — извлекает структурированные сущности (метрики, проекты, людей)
2. `track_promises` — извлекает обещания и дедлайны
3. `find_contradictions` — сравнивает новые метрики с уже существующими, фиксирует расхождения
4. `find_logic_signals` — запускает cross-document LLM-анализ после каждого нового документа

Шаги 3 и 4 порождают «фоновые сигналы» о противоречиях и логических конфликтах. На ранней стадии (до 50 документов) эти сигналы:
- Генерируются часто, многие — ложные (false positives из-за разного контекста)
- Засоряют БД нерелевантными предупреждениями, которые появляются в каждом ответе
- Создают лишнюю нагрузку на LLM API при каждой загрузке

Тесты на реальных данных (50 поведенческих тестов, май 2026) показали, что persistent hallucination state — главный источник деградации качества ответов.

## Решение

Добавить feature flag `ENABLE_BACKGROUND_SIGNALS` (default: `False`).

Когда `False`:
- `extract_entities` и `track_promises` работают как прежде
- `check_and_save_contradictions` и `find_logic_signals_for_document` пропускаются

Когда `True`:
- Всё работает как раньше

## Управление флагом

В `.env`:
```
ENABLE_BACKGROUND_SIGNALS=true
```

В `backend/app/settings.py`:
```python
ENABLE_BACKGROUND_SIGNALS: bool = False
```

## Последствия

**Положительные:**
- Ответы больше не засорены ложными предупреждениями при малом корпусе
- Indexing pipeline быстрее (на 1-2 LLM call меньше)
- Чище для onboarding новых пользователей

**Отрицательные:**
- Contradictions и logic signals не заполняются при indexing
- Таблицы `contradictions` и `logic_signals` остаются пустыми пока флаг выключен

**Когда включать:**
- Корпус > 30 документов с реальным контентом
- Прошёл ручной review первых документов — нет дубликатов/тестовых данных
- Запущен eval-set и baseline качества зафиксирован (Task 2.1)
