# План: вывести все бизнес-кейсы на целевой путь

**Дата:** 17 мая 2026 · **Связано:** `SCALE-PLAN.md`, `TZ.md`, `USE-CASES`

## Контекст

Описаны ~40 бизнес-кейсов использования AI Lab (см. чат-сессию /
будущий `USE-CASES.md`). Чтобы каждый кейс «проходил спокойно», система
должна быть собрана по **целевому пути**: мозг — Claude, он рассуждает и
сам ходит в интернет; `ai-lab-mcp` отдаёт данные; backend хранит и ищет.

Аудит кода (ветка `system-analysis-I209k`, 17.05) показал, что целевой
путь **в основном построен**, но рядом живёт второй, серверный «мозг»
(`/api/chat` → docs-agent → planner/self-check/web_research), и кейсы
через него не пойдут по целевой архитектуре. Этот план — как довести
целевой путь до конца.

## Целевой путь

```
Сотрудник → его Claude (мозг: рассуждение + веб) → ai-lab-mcp (данные) → backend (движок)
```

- **Claude** — весь интеллект; сам ходит в интернет за рыночным контекстом.
- **ai-lab-mcp** — 8 инструментов, чистый GET, ноль LLM.
- **backend** — хранение, чанкинг, эмбеддинги, retrieval; LLM только на индексации (детекторы).
- Логика рассуждения (режимы, факт/гипотеза, цитаты, охват) живёт в
  `ai-lab-skill/SKILL.md` — это «программа мозга», не серверный код.

Серверный `/api/chat` остаётся обслуживать React-панель; для 40 кейсов
он не используется и дальше не развивается.

## Этапы

### Этап 0 — Развязать живой путь (без токена, малый корпус)
- Поднять `backend` + `ai-lab-mcp` (`docker-compose`).
- Загрузить 10–30 реальных документов: `index_docs.py`, `ENABLE_BACKGROUND_SIGNALS=false`.
- Подключить `ai-lab-mcp` к Claude как remote-MCP, установить `ai-lab-skill`.
- Прогнать по 2–3 кейса групп A/B/C/F вживую.
- **Снимает риск** «MCP не прогонялся с живым Claude».

### Этап 1 — Масштаб корпуса + retrieval-гейт
- Загрузить корпус партиями 100→200→300 (`SCALE-PLAN.md`, без детекторов).
- После каждой партии — retrieval-гейт (Фаза 1.5), recall ≥80%.
- Просел recall — чинить retrieval (реранкинг, веса гибрида, чанкинг таблиц).
- **Открывает ~30 из 40 кейсов** (A, B, C, F, 4a, бо́льшая часть E) — Claude агентно.

### Этап 2 — «Бульон»: предвычисленные карточки (нужен токен Avito gateway)
- Получить токен Avito gateway *(организационный критический путь)*.
- Прогнать index-time детекторы (`ENABLE_BACKGROUND_SIGNALS=true`).
- Precision-ревью + независимая человеческая разметка (ТЗ §13.3).
- **Ускоряет** реестровые кейсы (PMO: «все расхождения / все просроченные обещания»).

### Этап 3 — 4b «Неувиденное»: рынок + дашборды
- **Рынок** — почти готово: Claude сам ходит в интернет; плейбук в `SKILL.md` есть.
- **Дашборды** — новая стройка: инструмент `ai-lab-mcp` `metrics_history(stream)`
  + бэкенд-коннектор к `dwh-redash-mcp` (коннекторы Avito AI преднастроены);
  детектор слепых метрик (Возможность 7B).
- **Открывает** группу D-4b и рыночные кейсы.

### Этап 4 — Пилот и проактив (опционально)
- `ai-lab-skill` → skills-hub, пилот на 3 сотрудниках ASD Goods.
- Проактив (ночной дайджест) — n8n, Фаза 4; требует структурного индекса.

## Матрица готовности кейсов

| Группа кейсов | Проходит после |
|---|---|
| F — поиск, онбординг | Этап 1 |
| A — числовые расхождения | Этап 1 (агентно) · Этап 2 для реестров |
| B — логические противоречия | Этап 1 |
| C — обещания | Этап 1 (агентно) · Этап 2 для реестров |

## Что строить кодом

1. **`ai-lab-skill/SKILL.md`** — полная «программа мозга»: режимы, факт/гипотеза,
   правила цитат, сравнение метрик, контракт охвата, плейбуки кейсов.
   Перенос логики из серверного `docs.py` на сторону Claude. *(Этап 0)*
2. **`metrics_history` инструмент** `ai-lab-mcp` + бэкенд-коннектор к
   `dwh-redash-mcp`; детектор слепых метрик. *(Этап 3 — основной объём.)*
3. **Retrieval-правки** — условно, если провалится гейт. *(Этап 1)*
4. **Решение, не код:** `/api/chat` серверный мозг — оставить для React-панели,
   дальше не развивать.

## Критический путь и риски

- **Токен Avito gateway** — блокирует только Этап 2. Этапы 0–1 и ~30 кейсов идут без него.
- **Качество retrieval на масштабе** — главный технический риск; ловится гейтом.
- **Precision слабых детекторов** — для интерактива обходится (Claude агентно).
- **Структурный индекс** для корпусного обхода — нужен только проактиву (Этап 4).

## Проверка

Acceptance — это сами 40 кейсов, прогнанные через Claude + `ai-lab-mcp`
(не через `/api/chat`). После Этапа 1 — прогон групп A–F; после Этапа 3 —
группа 4b. Каждый ответ несёт охват проверки (ТЗ §13.4).
