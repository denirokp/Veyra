# Gap-анализ: AI Lab против AI-экосистемы Avito

Документ сравнивает AI Lab с внутренним паттерном AI-агентов Avito (по
материалам внутреннего показа: 5 продуктовых проектов + инфраструктура
MCP Hub / Skills Hub / приложение Avito AI). Цель — отделить то, что в
AI Lab **уже совпадает** с паттерном, от **реальных расхождений**, и для
каждого расхождения дать варианты решения **без выбора одной реализации**.

Повод — принцип: «Если детекторы работают — дальше упаковываем в скилл.
Если врут — никакая красивость не спасёт». Показ Avito подтверждает его на
каждом проекте: метрики-ворота, автотесты, а слайд «Сложности» зрелого
скилла `quality-metrics` прямо пишет «требуется валидация результата».

Самодостаточный документ; термины — в §7 «Глоссарий».

---

## 1. Эталон — паттерн Avito

**Архитектура каждого проекта:** агент (Claude / Codex) + tool use →
данные за MCP-серверами → доменная логика в скилле → рассуждение у модели.

**Инфраструктура:**
- **MCP Hub** — единая точка входа во все MCP-серверы Avito (~19 серверов /
  500+ инструментов). Единый OAuth через Keycloak; **PII-анонимизация
  встроена** — автоматическое удаление персональных данных из запросов и
  ответов для серверов с чувствительными данными. Среди серверов:
  `data-docs-mcp` (метаданные DWH), `dwh-redash-mcp` (дашборды, 76 tools),
  `mcp-grafana` (панели, метрики), `trisigma-mcp` (семантический слой,
  AB-кубы), `querypad` (SQL по DWH).
- **Skills Hub** — маркетплейс устанавливаемых скиллов в формате `SKILL.md`
  (`SKILL.md` + `scripts/` + `references/` + `assets/`), с поиском,
  владельцами и счётчиками установок (`avito ai skills search`).
- **Avito AI** — десктоп-приложение: выбор агента (Claude Dev/Desktop,
  Codex), тумблеры «Использовать MCP Hub» / «Avito MCP».

**Продуктовые проекты (эталоны зрелости):** договорная работа (проверка
договоров), SEO-аналитика (агент + 6 tools + DWH), Risk Digest (n8n,
внешний поиск), `quality-metrics` (скилл анализа метрик качества), проверка
креативов (Python orchestration).

**Сквозные принципы показа:**
- Поэтапный rollout с kill-point; метрики-ворота (точность >80% на MVP →
  >90% после теста; ≥90% релевантности у Risk Digest).
- Дисциплина валидации: «измерять результат сразу после внедрения»,
  «автотесты при изменении промптов — прогон на ограниченной выборке»,
  Golden Set верифицированных запросов, LLM-judges для eval.
- Контроль стоимости: «6–10 tool-calls на запрос, при масштабе нужен
  мониторинг»; исчерпание токенов в окне как реальная проблема.

## 3. Гэпы

### G1. Точность детекторов не провалидирована — **главный гэп**

- **Эталон Avito:** скилл `quality-metrics` использует LLM-judges для eval
  и прямо отмечает «требуется валидация результата»; SEO-агент опирается на
  Golden Set из 18 верифицированных SQL; каждый проект меряет результат
  после внедрения.
- **AI Lab сейчас:** eval-харнес прогнан (3 документа) — precision: обещания
  94%, логические сигналы 83%, числовые расхождения 11%. По числовым
  сделаны две попытки предвычисления: LLM-схема фабриковала (11%),
  переписанная детерминированная — на 3 документах гейта дала 0; на корпусе
  28 документов вскрыла шум: 162 ложные пары (коллизии периода и
  перегруженные имена-таблицы), два фикса (период-None, гард `≥3 значений`)
  свели к 19, из них ~6 реальных. Вывод: предвычислять числовые расхождения
  детектором — тупик; их ищет Claude на запросе, что и подтвердил гейт
  Фазы 1. Логический и promise-детекторы валидны и работают. Открыто:
  независимая человеческая разметка ground truth для логики и обещаний.
- **Варианты решения:**
  - (a) **Человеческий golden set** — аналитик независимо размечает выборку
    расхождений/обещаний; считать precision как «доля подтверждённых».
  - (b) **Eval-харнес на LLM-judge** — по образцу скилла `quality-metrics`
    Avito: судья-модель проверяет каждую находку детектора против
    документа-источника.
  - (c) **Оба** — LLM-judge для масштаба, человеческая выборка для
    калибровки судьи.

### G2. `ai-lab-mcp` не готов к MCP Hub

- **Эталон Avito:** серверы в Hub — remote, единый OAuth через Keycloak,
  зарегистрированы в registry; подключается один Hub вместо N серверов.
- **AI Lab сейчас:** `ai-lab-mcp/server.py` — отдельный FastMCP, transport
  `streamable-http`, авторизация — статичный bearer-токен
  (`AILAB_BACKEND_TOKEN`), стадия alpha, в registry не зарегистрирован.
- **Варианты решения:**
  - (a) Зарегистрировать `ai-lab-mcp` как remote-MCP за Hub — наследует
    OAuth и PII-анонимизацию Hub, отдельная настройка не нужна.
  - (b) Оставить standalone сейчас, зафиксировать Hub как целевое состояние
    в `ARCHITECTURE.md`.
  - (c) Гибрид — standalone сейчас, заранее заложить Hub-совместимую модель
    авторизации.

### G3. Нет PII-анонимизации

- **Эталон Avito:** Hub автоматически удаляет персональные данные из
  запросов и ответов для серверов с чувствительными данными.
- **AI Lab сейчас:** слоя анонимизации нет — фрагменты корпуса уходят в
  Claude как есть (поиск по репозиторию: `anonymiz`/`redact`/`PII` —
  совпадений нет).
- **Варианты решения:**
  - (a) Положиться на PII-анонимизацию Hub (ноль кода AI Lab) при деплое за
    Hub — гэп закрывается вместе с G2.
  - (b) Добавить локальный redaction-проход для деплоя вне Hub.
  - (c) Принять как есть, если корпус не содержит PII — явно
    задокументировать это допущение.

### G4. Нет регрессионного харнеса на изменения скилла/промптов

- **Эталон Avito:** Risk Digest — «автотесты при изменении промптов: запуск
  workflow на ограниченной выборке»; `quality-metrics` отмечает потребность
  в отладке.
- **AI Lab сейчас:** построен регрессионный харнес `scripts/regression.py`
  (G4) — помнит baseline, сравнивает recall/precision; git-хук
  `scripts/hooks/pre-push` гоняет его при изменении поведенческих файлов
  (SKILL.md, промпты детекторов). Не прогнан — нужен бэкенд + корпус +
  `LLM_API_KEY`. Регрессия живого пути SKILL.md (Claude + ai-lab-mcp) пока
  не автоматизирована.
- **Варианты решения:**
  - (a) Превратить гейт в CI-прогоняемый регрессионный набор на
    фиксированной выборке.
  - (b) Sample-eval по триггеру правки скилла/промптов.
  - (c) Объединить с eval-харнесом из G1 (один прогоняемый набор).

### G5. `ai-lab-skill` не опубликован в Skills Hub

- **Эталон Avito:** Skills Hub — поиск, установка, владельцы, счётчики
  установок.
- **AI Lab сейчас:** `ai-lab-skill/` существует только локально; формат
  `SKILL.md` уже совместим (см. A2).
- **Варианты решения:**
  - (a) Опубликовать в Skills Hub **после** прохождения G1 — ровно по
    принципу «если детекторы работают — упаковываем в скилл».
  - (b) Перед публикацией сверить frontmatter `SKILL.md` с требованиями
    Hub (формально `name` + `description` уже есть).
  - (c) Отложить до закрытия G1 + G2.

### G6. Нет мониторинга стоимости и числа вызовов

- **Эталон Avito:** «6–10 tool-calls на запрос, при масштабе нужен
  мониторинг»; `quality-metrics` упёрся в исчерпание токенов в окне.
- **AI Lab сейчас:** нет логирования числа tool-call / латентности /
  стоимости на живом пути (Claude → `ai-lab-mcp`).
- **Варианты решения:**
  - (a) Добавить логирование числа tool-call и латентности в `ai-lab-mcp`.
  - (b) Отложить до прохождения валидации (G1).

### G7. `STATUS.md` — снимок на дату, живого roadmap нет

- **Эталон Avito:** `mcp-timeline` (Roadmap + Gantt) — отдельный артефакт.
- **AI Lab сейчас:** `docs/STATUS.md` привязан к дате и устаревает;
  отдельного `ROADMAP` нет.
- **Варианты решения:**
  - (a) Добавить `docs/ROADMAP.md` с фазовой моделью (Фазы 1 / 1.5 / 2 / 3).
  - (b) Оставить `STATUS.md` как есть.

## 4. Приоритет

Упорядочивание (не выбор реализации):

1. **G1 — ворота.** Пока precision детекторов не доказан, публикация скилла
   (G5) преждевременна. Это и есть «если детекторы врут — никакая красивость
   не спасёт».
2. **G4** — длящаяся форма G1: чтобы валидация не разово, а на каждое
   изменение скилла.
3. **G2** (а с ним и **G3** — PII-анонимизация приходит из Hub) — деплой-тайм,
   малые усилия со стороны AI Lab.
4. **G5** — публикация в Skills Hub после прохождения G1.
5. **G6 / G7** — дешёвая гигиена, попутно.

Очередь: **G1 → G4 → G2 (+G3) → G5; G6/G7 попутно.**

Этапы закрытия гэпов:

| Этап | Гэпы | Содержание |
|---|---|---|
| Этап 1 | G1, G4 | Валидация детекторов + регрессионный харнес. **Ворота релиза.** |
| Этап 2 | G2, G3, G5 | Интеграция в инфраструктуру Avito: MCP Hub, Skills Hub. |
| Этап 3 | G6, G7 | Эксплуатация: мониторинг стоимости, живой roadmap. |

## 5. Что закрывается без инфраструктуры Avito

Разделение для планирования спринтов — что реализуемо в репозитории AI Lab,
а что упирается во внешние доступы Avito.

**Сделано в репозитории:**
- G1 — eval-харнес `scripts/eval_detectors.py` построен и прогнан:
  precision на 3 документах — обещания 94%, логика 83%, числовые 11%.
- По итогам — числовой детектор переписан на детерминированную схему;
  прогон 28 документов вскрыл шум (162 ложные пары), два фикса (период-None
  и гард `≥3 значений`, перепроверены `scripts/retest_numeric.py`) свели
  к 19; числовые расхождения закреплены за Claude на запросе. У логических
  находок — светофор severity, `SKILL.md` выводит 2 таблицы несоответствий.
- G4 — регрессионный харнес `scripts/regression.py` + git-хук
  `scripts/hooks/pre-push`; `run_gate.py` пишет `gate_summary.json`.
- `docs/USE-CASES.md` — каталог кейсов в формате JTBD (предусловие G5).

**Осталось сделать в репозитории (без доступов Avito):**
- G5-предусловие — сверка frontmatter `ai-lab-skill/skills/SKILL.md` (формально
  `name` + `description` уже есть);
- G6 — логирование числа tool-call / латентности в `ai-lab-mcp`;
- G7 — `docs/ROADMAP.md`;
- G3 вариант (b) — локальный redaction-проход.

**Частично:**
- G1 — независимая человеческая разметка ground truth: работа аналитика,
  не автоматизируется. Без неё валидация остаётся частично циклической.

**Заблокировано доступами/инфраструктурой Avito:**
- G2 — регистрация `ai-lab-mcp` в MCP Hub, OAuth через Keycloak;
- G3 вариант (a) — PII-анонимизация силами Hub;
- G5 — публикация `ai-lab-skill` в Skills Hub.

**Вывод по готовности к релизу.** Каркасы G1 и G4 построены, но **не
прогнаны** — система к публикации в Avito пока не готова. Этап 1 (ворота
релиза) закрывается так: прогнать `eval_detectors.py` на реальном корпусе,
завести baseline регрессии, получить независимую разметку аналитиком.
Интеграция в Avito (Этап 2 — G2 / G3 / G5) зависит от доступов к MCP Hub
и Skills Hub.

## 7. Глоссарий

- **MCP Hub** — единая точка входа Avito во все MCP-серверы: один OAuth,
  PII-анонимизация, ~500+ инструментов.
- **Skills Hub** — маркетплейс устанавливаемых скиллов Avito в формате
  `SKILL.md`.
- **Avito AI** — десктоп-приложение Avito для запуска агентов с
  подключённым MCP Hub.
- **Детектор** — index-time skill AI Lab, который при индексации ищет в
  корпусе расхождения/обещания/логические сигналы («бульон»).
- **Гейт** — прогон проверки качества находок (`scripts/run_gate.py`).
- **Циклический ground truth** — эталон, размеченный той же моделью, что и
  детектор: меряет самосогласованность, не правильность.
- **Precision** — доля находок детектора, оказавшихся верными.
- **LLM-judge** — модель-судья, проверяющая находку против источника.
- **PII-анонимизация** — удаление персональных данных перед отправкой во
  внешнюю модель.
