**Версия:** 1.0 · 17 мая 2026
Самодостаточный документ: вся логика, структура, бизнес-смысл и границы.
Связанные документы — `ARCHITECTURE.md` (глубже про слои), `SCALE-PLAN.md`

> кодовик; отсюда имена в коде: `khronika.db`, коллекции ChromaDB

## 1. Зачем AI Lab существует — бизнес-проблема с нуля

Коммерческий блок Avito (ASD Goods, CCO Алексей Ли) постоянно
производит стратегические документы — стратегии, ресёрчи, планы,
разборы. Их **сотни**, лежат в Confluence, авторы пересекаются.

Проблема: **никто не держит весь массив в голове.** Из-за этого:
- документ A говорит «сегмент растёт», документ B (полгода спустя) —
  «сегмент падает», и это никто не свёл;
- в стратегии что-то пообещали — через год не сделали, и это не видно;
- в финмодель заложили цифру, которая не сходится с цифрой в FAQ того
  же документа;
- метрику, которую стоило бы отслеживать, просто забыли.

Эти расхождения **накапливаются и не ловятся вручную** — человек не
перечитывает 300 документов перед каждым решением.

**Задача Алексея** (встреча 07.05.2026): инструмент, который загружает
документы команды — «бульон» — и проверяет числа **и логику** на
противоречия, отслеживает обещал/сделал, подсвечивает слепые зоны,
сверяет с рынком, сводит новые инициативы со всем накопленным. И
работает не как отдельный продукт, а внутри Claude.

AI Lab — ответ на эту задачу.

## 2. Что AI Lab делает

Задача Алексея распадается на **два типа вопросов**.

**Где документы спорят (смотрит в корпус):**
- **числовые расхождения** — одна метрика, разные значения;
- **логические противоречия** — «здесь говорим одно, здесь другое»;
- **невыполненные обещания** — обещал / сделал;
- **пробелы** — «провалили между стульев»: что обсуждали или
  подразумевали, но не закрыли планом.

**Чего мы не видим (смотрит за пределы корпуса):**
- **неувиденные возможности и гипотезы** — какие идеи и направления мы
  упускаем. Этого в документах нет вообще, поэтому система ищет не в
  корпусе, а **сверяя корпус с тремя внешними рамками**:
  - **рынок** — какие практики есть снаружи, которых нет у нас;
  - **дашборды и метрики** — какие метрики стоит смотреть, но не смотрим;
  - **другие направления Avito** — что делают соседние стримы (Фаза 3).

Каждая находка — **с цитатой и ссылкой на источник** (для «неувиденного»
— с указанием, на какой внешней рамке основана гипотеза).

> **Важно про «серые зоны».** В быту это слово смешивает две разные
> задачи. «Пробелы» (выше) выводятся из корпуса. «Неувиденное» из
> корпуса вывести нельзя — нельзя найти то, чего в документах нет, читая
> то, что в них есть. Поэтому это разные механизмы, а рынок и дашборды —
> **не вспомогательные фичи, а рабочий инструмент** второго типа вопросов.

**Чего AI Lab НЕ делает:** не пишет документы вместо человека, не
заменяет обычный поиск по Confluence. Её ниша — **логика: где документы
спорят и чего в них не хватает**.

## 3. Как это работает бизнесово

AI Lab — **не сайт**. Это навык внутри помощника (Claude / Avito AI),
которым сотрудник уже пользуется в работе.

Сценарий:
1. Аналитик пишет инициативу или готовит решение.
2. Спрашивает своего помощника: «Проверь инициативу X», «Что мы
   обещали по обучению продавцов?», «Нет ли противоречий с прошлыми
   решениями?».
3. Помощник через MCP обращается к AI Lab, подтягивает релевантные
   документы и факты, и отвечает — со ссылками на источники.

**Ценность:** за секунды то, на что аналитик потратил бы часы — и всё
равно пропустил бы нестыковку, зарытую в приложении 50-страничного
документа. AI Lab её находит.

«Бульон» (метафора Алексея) — это и есть разобранный, проиндексированный
корпус: субстрат, из которого система «варит» любой ответ.

## 4. Архитектура — три слоя

```
┌──────────────────────────────────────────────────────────────┐
│  СЛОЙ 3 — CLAUDE  (весь интеллект, сторона клиента)           │
│  агентный цикл: ищет → читает → докапывается → сверяет        │
│  синтез ответа · написание · веб-поиск · вердикт              │
└───────────────────────────┬──────────────────────────────────┘
                            │ MCP (streamable-http)
┌───────────────────────────▼──────────────────────────────────┐
│  СЛОЙ 2 — ai-lab-mcp  (фасад данных, НОЛЬ LLM)                 │
│  8 инструментов: поиск, документы, расхождения, обещания      │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTP
┌───────────────────────────▼──────────────────────────────────┐
│  СЛОЙ 1 — backend-движок                                      │
│  хранение · чанкинг · эмбеддинги · retrieval                  │
│  ChromaDB (вектора кусков) + SQLite (документы, карточки)     │
└────────────────────────────────────────────────────────────────┘
```

**Принцип:** интеллект — у Claude (лучшая модель, видит контекст
вопроса). Сервер — быстрый, дешёвый поставщик материала. Библиотекарь
приносит книги, аналитику пишет аналитик. Подробно — `ARCHITECTURE.md`.

## 6. Как взаимодействовать с системой

### 6.1. Загрузить документы

```bash
# .env: ENABLE_BACKGROUND_SIGNALS=false  — быстрая загрузка без LLM
python3 scripts/index_docs.py            # первичная: сброс + индексация всех
python3 scripts/index_docs.py --sync     # инкремент: новые + изменённые
```
Документы кладутся в `backend/data/docs/`. Подробнее — `SCALE-PLAN.md`.

### 6.2. Запустить движок

```bash
cd backend && uvicorn app.main:app        # :8000
```
Или всё разом: `docker compose up`.

### 6.3. Спросить — через MCP-инструменты AI Lab

Помощник Claude с подключённым MCP-сервером `ai-lab` вызывает:

| Инструмент | Назначение |
|---|---|
| `search_corpus(query)` | релевантные фрагменты корпуса |
| `get_document(id)` | полный текст документа |
| `list_documents()` | список документов |
| `find_numeric_contradictions()` | числовые расхождения (таблица) |
| `find_logic_contradictions()` | логические расхождения (таблица) |
| `find_open_promises()` | незакрытые обещания |
| `corpus_stats()` | сводка по корпусу |
| `health()` | доступность движка |

### 6.4. Проверить детекторы / масштаб

```bash
python3 scripts/run_gate.py --retrieval --runs 3   # recall по трекам
python3 scripts/eval_detectors.py                  # precision детекторов (LLM-judge)
python3 scripts/regression.py                      # регрессия против baseline
```
`run_gate.py` считает recall, `eval_detectors.py` — precision находок
детекторов, `regression.py` сравнивает обе метрики с зафиксированным
baseline (см. также git-хук `scripts/hooks/pre-push`).

## 8. Слабые места — честно

1. **Retrieval на масштабе не проверен.** Гейт прогонялся на 3
   документах. На 300 — recall неизвестен. Это главный риск; ловится
   инкрементальной загрузкой с гейтом после каждой партии.
2. **Числовой детектор как предвычислитель — закрыт.** Eval дал precision:
   обещания 94%, логика 83% (рабочие), числовые 11%. Числовой детектор
   переписан на детерминированную схему — фабрикацию убрал, но строгий
   матч имени даёт 0 находок. Вывод: предвычислять числовые расхождения
   детектором не получается ни LLM-, ни детерминированной схемой — их
   ищет Claude на запросе (гейт Фазы 1 подтвердил). Детектор оставлен
   включённым как безвредный safety-net.
3. **Тихий ложный негатив.** Если retrieval не поднял нужный кусок,
   ответ «расхождений нет» будет неполным. Митигация — каждый ответ
   несёт охват проверки.
4. **Циклический ground truth.** Разметка гейта сделана Claude — гейт
   меряет самосогласованность модели, не истину. Нужна человеческая
   разметка.
5. **ai-lab-mcp не прогонялся против живого Claude** — проверен только
   импортом.
6. **Корпусный проактивный обход** («найди ВСЕ противоречия») на 300
   документах требует структурного индекса-кластеризации — не построен.
7. **LLM-доступ.** Личный ключ Anthropic упирается в rate-limit и
   кредиты. Нужен токен Avito gateway.
8. **SQLite** — конкурентная запись мультиюзера; на масштабе
   пользователей — Postgres.
9. **Мониторинг** — только health-чеки; метрик и алертов нет (в проде —
   через инфру Avito).
10. **Фронтенд избыточен** — в MCP-модели AI Lab доходит через помощника;
    React-сайт не путь доставки, может быть убран или оставлен как
    админ-панель.

## 9. Статус и что дальше

**Показано (в границах одного прогона):** на 3 документах в full-text
режиме Claude нашёл 4 из 5 размеченных расхождений, с цитатами, без
видимых галлюцинаций. Это **не измерение**: один прогон (ТЗ §13.8
требует ≥3), precision не считался, ground truth размечен Claude
(самосогласованность, не истина). Подробные границы — `gate_report.md`.

**Не доказано:** масштаб (retrieval на 300), precision детекторов,
живой прогон MCP с Claude, дашборды. Самый большой риск — retrieval на
масштабе (см. §8, пункт 1).

**Ближайшие шаги:**
1. С понедельника — загрузка корпуса 100→300 документов **без
   детекторов** (быстро, бесплатно, без токена). См. `SCALE-PLAN.md`.
2. После каждой партии — гейт, мониторинг recall.
3. Токен Avito gateway → «бульон» (детекторы), структурный индекс,
   дашборды, деплой на PaaS.
4. Пилот на 3 сотрудниках ASD Goods.

AI Lab — это глупый быстрый движок памяти + агентный Claude поверх.
Движок построен и проверен; интеллект — у Claude; доставка — через MCP.
Дальше — масштаб и площадка.

## 10. Глоссарий

| Термин | Значение |
|---|---|
| **Бульон** | метафора Алексея — разобранный, проиндексированный корпус: субстрат знаний, из которого система «варит» любой ответ. |
| **Детектор** | компонент, который находит факт о корпусе (расхождение, обещание, пробел). Валидируется гейтом по recall/precision. |
| **Генератор / обогатитель** | компонент, который пишет текст или тянет внешние данные (рыночный контекст, черновик). Валидируется своим баром качества, не гейтом расхождений. |
| **Гейт** | проверка детекторов: прогон размеченных вопросов и сверка находок с ground truth. Цель — доказать, что детектор не врёт. |
| **Ground truth** | эталонная разметка (что является настоящим расхождением) — `scripts/gate_ground_truth.json`. |
| **Recall / precision** | recall — доля настоящих находок, которые детектор нашёл; precision — доля находок детектора, которые настоящие. |
| **Охват** | в ответе — что и где система проверила («проверено N из M документов»). Запрет отвечать «расхождений нет» без охвата (ТЗ §13.4). |
| **Grounding** | фильтр галлюцинаций: каждое утверждение сверяется с источником, неподтверждённое отбрасывается. |
| **Drop-rate** | доля фактов, отброшенных grounding-фильтром. |
| **RRF** (Reciprocal Rank Fusion) | способ слить два ранжирования (вектор + BM25) в одно по формуле `1/(k+rank)`. |
| **Retrieval** | поиск релевантных кусков корпуса под запрос; в AI Lab — гибридный (вектор + BM25 + RRF + boost по иерархии). |
| **Чанк / кусок** | фрагмент документа после нарезки, единица индексации и поиска. |
| **MCP** (Model Context Protocol) | протокол, по которому Claude вызывает внешние инструменты; `ai-lab-mcp` — MCP-сервер AI Lab. |
| **L1–L7** | уровни иерархии документа: L1 — якорный, L2 — стратегия, L3 — ресёрч/план, L4 — операционный, L5 — черновик/неизвестный, L6 — архивный, L7 — заменённый (исключается). |
| **Index-time детекторы** | детекторы, запускаемые при индексации документа (управляются флагом `ENABLE_BACKGROUND_SIGNALS`). |
| **Структурный индекс** | дешёвый индекс «метрика/тема → какие документы её касаются» для корпусного проактивного обхода (спроектирован, не построен). |
| **Пробелы** (Возм. 4a) | что обсуждали/обещали в корпусе, но не закрыли планом — «провалили между стульев». Видно из корпуса; скилл `find_gaps`. |
| **Неувиденное** (Возм. 4b) | какие идеи/гипотезы/метрики мы упускаем — чего в корпусе нет вообще. Из корпуса не выводится; ищется сверкой с рынком и дашбордами. |
| **Серые зоны** | бытовой зонтик-термин; смешивает «пробелы» (4a) и «неувиденное» (4b). В документах используются раздельные термины. |
| **Кросс-опыление** | сверка корпуса с внешней рамкой (рынок / дашборды / другие направления Avito) для поиска «неувиденного». |
