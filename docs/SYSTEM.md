# Veyra — полное описание системы

**Версия:** 1.0 · 17 мая 2026
Самодостаточный документ: вся логика, структура, бизнес-смысл и границы.
Связанные документы — `ARCHITECTURE.md` (глубже про слои), `SCALE-PLAN.md`
(загрузка корпуса), `STATUS.md` (статус сессии).

---

## 1. Зачем Veyra существует — бизнес-проблема с нуля

Коммерческий блок Avito (ASD Goods, CCO Алексей Ли) постоянно
производит стратегические документы — стратегии, ресёрчи, планы,
разборы. Их **сотни**, лежат в Confluence, авторы пересекаются.

Проблема: **никто не держит весь массив в голове.** Из-за этого:
- документ A говорит «сегмент растёт», документ B (полгода спустя) —
  «сегмент падает», и это никто не свёл;
- в стратегии что-то пообещали — через год не сделали, и это не видно;
- в финмодель заложили цифру, которая не сходится с цифрой в FAQ того
  же документа;
- метрику, которую стоило бы отслеживать, просто забыли.

Эти расхождения **накапливаются и не ловятся вручную** — человек не
перечитывает 300 документов перед каждым решением.

**Задача Алексея** (встреча 07.05.2026): инструмент, который загружает
документы команды — «бульон» — и проверяет числа **и логику** на
противоречия, отслеживает обещал/сделал, подсвечивает слепые зоны,
сверяет с рынком, сводит новые инициативы со всем накопленным. И
работает не как отдельный продукт, а внутри Claude.

Veyra — ответ на эту задачу.

---

## 2. Что Veyra делает

**Находит в стратегических документах:**
- **числовые расхождения** — одна метрика, разные значения;
- **логические противоречия** — «здесь говорим одно, здесь другое»;
- **невыполненные обещания** — обещал / сделал;
- **серые зоны** — инициативы без ресурсов, владельцев, метрик.

Каждая находка — **с цитатой и ссылкой на документ-источник**.

**Чего Veyra НЕ делает:** не пишет документы вместо человека, не
заменяет обычный поиск по Confluence. Её ниша — **логика противоречий**.

---

## 3. Как это работает бизнесово

Veyra — **не сайт**. Это навык внутри помощника (Claude / Avito AI),
которым сотрудник уже пользуется в работе.

Сценарий:
1. Аналитик пишет инициативу или готовит решение.
2. Спрашивает своего помощника: «Проверь инициативу X», «Что мы
   обещали по обучению продавцов?», «Нет ли противоречий с прошлыми
   решениями?».
3. Помощник через MCP обращается к Veyra, подтягивает релевантные
   документы и факты, и отвечает — со ссылками на источники.

**Ценность:** за секунды то, на что аналитик потратил бы часы — и всё
равно пропустил бы нестыковку, зарытую в приложении 50-страничного
документа. Veyra её находит.

«Бульон» (метафора Алексея) — это и есть разобранный, проиндексированный
корпус: субстрат, из которого система «варит» любой ответ.

## 4. Архитектура — три слоя

```
┌──────────────────────────────────────────────────────────────┐
│  СЛОЙ 3 — CLAUDE  (весь интеллект, сторона клиента)           │
│  агентный цикл: ищет → читает → докапывается → сверяет        │
│  синтез ответа · написание · веб-поиск · вердикт              │
└───────────────────────────┬──────────────────────────────────┘
                            │ MCP (streamable-http)
┌───────────────────────────▼──────────────────────────────────┐
│  СЛОЙ 2 — veyra-mcp  (фасад данных, НОЛЬ LLM)                 │
│  8 инструментов: поиск, документы, расхождения, обещания      │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTP
┌───────────────────────────▼──────────────────────────────────┐
│  СЛОЙ 1 — backend-движок                                      │
│  хранение · чанкинг · эмбеддинги · retrieval                  │
│  ChromaDB (вектора кусков) + SQLite (документы, карточки)     │
└────────────────────────────────────────────────────────────────┘
```

**Принцип:** интеллект — у Claude (лучшая модель, видит контекст
вопроса). Сервер — быстрый, дешёвый поставщик материала. Библиотекарь
приносит книги, аналитику пишет аналитик. Подробно — `ARCHITECTURE.md`.

## 6. Как взаимодействовать с системой

### 6.1. Загрузить документы

```bash
# .env: ENABLE_BACKGROUND_SIGNALS=false  — быстрая загрузка без LLM
python3 scripts/index_docs.py            # первичная: сброс + индексация всех
python3 scripts/index_docs.py --sync     # инкремент: новые + изменённые
```
Документы кладутся в `backend/data/docs/`. Подробнее — `SCALE-PLAN.md`.

### 6.2. Запустить движок

```bash
cd backend && uvicorn app.main:app        # :8000
```
Или всё разом: `docker compose up`.

### 6.3. Спросить — через MCP-инструменты Veyra

Помощник Claude с подключённым MCP-сервером `veyra` вызывает:

| Инструмент | Назначение |
|---|---|
| `search_corpus(query)` | релевантные фрагменты корпуса |
| `get_document(id)` | полный текст документа |
| `list_documents()` | список документов |
| `find_numeric_contradictions()` | числовые расхождения (таблица) |
| `find_logic_contradictions()` | логические расхождения (таблица) |
| `find_open_promises()` | незакрытые обещания |
| `corpus_stats()` | сводка по корпусу |
| `health()` | доступность движка |

### 6.4. Проверить детекторы / масштаб

```bash
python3 scripts/run_gate.py --retrieval --runs 3
```
Прогоняет 5 размеченных вопросов, считает recall по трекам.

## 8. Слабые места — честно

1. **Retrieval на масштабе не проверен.** Гейт прогонялся на 3
   документах. На 300 — recall неизвестен. Это главный риск; ловится
   инкрементальной загрузкой с гейтом после каждой партии.
2. **Детекторы слабые.** Серверные LLM-детекторы давали 0/0/0, потом
   шумные результаты. Доказанно работает Claude над полным текстом, не
   детекторы. Целевая архитектура — заменить детекторы агентным Claude
   (но это Фаза 2; пока детекторы оставлены как переходный слой).
3. **Тихий ложный негатив.** Если retrieval не поднял нужный кусок,
   ответ «расхождений нет» будет неполным. Митигация — каждый ответ
   несёт охват проверки.
4. **Циклический ground truth.** Разметка гейта сделана Claude — гейт
   меряет самосогласованность модели, не истину. Нужна человеческая
   разметка.
5. **veyra-mcp не прогонялся против живого Claude** — проверен только
   импортом.
6. **Корпусный проактивный обход** («найди ВСЕ противоречия») на 300
   документах требует структурного индекса-кластеризации — не построен.
7. **LLM-доступ.** Личный ключ Anthropic упирается в rate-limit и
   кредиты. Нужен токен Avito gateway.
8. **SQLite** — конкурентная запись мультиюзера; на масштабе
   пользователей — Postgres.
9. **Мониторинг** — только health-чеки; метрик и алертов нет (в проде —
   через инфру Avito).
10. **Фронтенд избыточен** — в MCP-модели Veyra доходит через помощника;
    React-сайт не путь доставки, может быть убран или оставлен как
    админ-панель.

## 9. Статус и что дальше

**Доказано:** Veyra находит настоящие расхождения и не галлюцинирует
(гейт 4/5 на full-text). Самая рискованная часть — детектор-не-врёт —
снята.

**Не доказано:** масштаб (retrieval на 300), живой прогон MCP с Claude,
дашборды.

**Ближайшие шаги:**
1. С понедельника — загрузка корпуса 100→300 документов **без
   детекторов** (быстро, бесплатно, без токена). См. `SCALE-PLAN.md`.
2. После каждой партии — гейт, мониторинг recall.
3. Токен Avito gateway → «бульон» (детекторы), структурный индекс,
   дашборды, деплой на PaaS.
4. Пилот на 3 сотрудниках ASD Goods.

Veyra — это глупый быстрый движок памяти + агентный Claude поверх.
Движок построен и проверен; интеллект — у Claude; доставка — через MCP.
Дальше — масштаб и площадка.
