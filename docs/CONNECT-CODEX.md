# AI Lab в Codex — настройка по шагам

Подключение MCP-сервера `ai-lab` к **приложению Codex** (десктоп/IDE OpenAI).
Как и в Claude.ai, нужны две вещи: **инструменты** (сервер ai-lab по URL) и
**правила** (`AGENTS.md`, т.к. у Codex нет механизма «skills», как у Claude).
Всё делается внутри приложения — терминал не нужен. ~5 минут.

**Перед началом:**
- Установлено приложение **Codex** (десктоп или расширение в IDE), ты залогинен.
- Есть файл `ai-lab/AGENTS.md` из репозитория Veyra (пришлёт Денис).
- Если api.openai.com у тебя недоступен — включи VPN.

---

## Шаг 1 — подключить данные (сервер ai-lab)

Codex хранит подключения в файле `config.toml`. В приложении до него можно
дойти мышкой, без терминала:

1. Открой приложение **Codex**.
2. Значок **шестерёнки** ⚙️ → **MCP settings** → **Open config.toml**.
   Откроется текстовый файл настроек.
3. Допиши в конец файла блок и **сохрани**:

   ```toml
   [mcp_servers.ai-lab]
   url = "https://veyra.fly.dev/mcp"
   ```

Что это делает: регистрирует remote streamable-HTTP сервер `ai-lab` по URL.
Сервер открытый — **токен не нужен**, поля авторизации не заполняем.

> Если позже включат `MCP_AUTH_TOKEN`, добавь в этот блок строку
> `bearer_token_env_var = "AILAB_TOKEN"` и положи токен в переменную окружения
> `AILAB_TOKEN` (Codex, в отличие от Claude.ai, умеет статичный Bearer).

## Шаг 2 — дать правила (`AGENTS.md`)

Это «мозги скилла» — grounding, контракт охвата, плейбуки, память находок.
Codex читает `AGENTS.md` из папки открытого проекта.

**Вариант А — для конкретного проекта (проще):**
положи файл `ai-lab/AGENTS.md` в **папку проекта, который открываешь в Codex**.
Правила активны, когда работаешь в этой папке.

**Вариант Б — глобально (во всех проектах):**
положи тот же файл как `~/.codex/AGENTS.md` — это та же папка настроек Codex,
где лежит `config.toml` из шага 1. Правила в `AGENTS.md` условные («когда
просят проверить инициативу / расхождения / …»), так что обычным задачам
кодинга не мешают.

## Шаг 3 — проверить

**Перезапусти** Codex (чтобы он подхватил новый сервер) и в чате напиши
обычными словами:

```
вызови ai-lab corpus_stats
```

Ожидаемо: вернётся число документов (**128**) и `last_indexed_at`. Дальше
можно обычными словами: «проверь инициативу: …», «какие обещания по … не
закрыты», «нет ли расхождений по GMV».

---

## Если что-то не так

| Симптом | Что сделать |
|---|---|
| Codex не видит инструменты `ai-lab` | Проверь, что строки из шага 1 сохранились (⚙️ → MCP settings → Open config.toml), и **перезапусти** Codex. Список подключённых MCP — командой `/mcp` в чате. |
| Ошибка про `url` / «server not supported» | Обнови приложение Codex — подключение сервера по URL (streamable HTTP) это относительно свежая возможность. |
| `401/403` от сервера | Сервер открытый, токен не нужен. Если включён `MCP_AUTH_TOKEN` — добавь `bearer_token_env_var` (см. Шаг 1). |
| «Рассуждает не по правилам» | Проверь, что `AGENTS.md` лежит в папке открытого проекта (или как `~/.codex/AGENTS.md`). |

## Codex CLI (если у кого-то терминальная версия)

В CLI до `config.toml` можно дойти напрямую, файл тот же — `~/.codex/config.toml`:

```bash
# 1. инструменты
mkdir -p ~/.codex
printf '\n[mcp_servers.ai-lab]\nurl = "https://veyra.fly.dev/mcp"\n' >> ~/.codex/config.toml

# 2. правила (глобально)
cp path/to/Veyra/ai-lab/AGENTS.md ~/.codex/AGENTS.md

# 3. проверка
codex   # → «вызови ai-lab corpus_stats»
```
